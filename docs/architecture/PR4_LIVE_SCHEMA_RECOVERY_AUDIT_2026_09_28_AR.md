## العوائق والخطوة اللازمة

1. غياب اعتماد اتصال PostgreSQL في بيئة العملية: لم توجد `PGPASSWORD, PGPASSFILE, SUPABASE_DB_PASSWORD, SUPABASE_DB_URL, DATABASE_URL`. قراءة SQL عبر الموصل لا توفر تلقائيًا اعتماد pg_dump. لم يُنشأ دور مؤقت ولم تُبحث كلمات المرور في سجلات المستخدم.
2. لم يتوفر مسار آمن معتمد لملف اعتماد موجود مسبقًا ولا وجهة للنسخة المشفرة ونسخة خارج جهاز التنفيذ. طُلبت **المسارات فقط** أثناء الجلسة؛ لا تُرسل كلمات المرور في المحادثة.
3. بعد توفيرهما: يلزم تصدير منطقي متسق ومشفر بمصدر قراءة فقط، يتضمن مخططات التطبيق وAuth والبيانات وتبعيات الأدوار دون كلمات مرور الأدوار، مع توثيق مستثنيات مخططات Supabase المدارة. يجب معالجة Storage الفعلي منفصلًا؛ نسخ قاعدة البيانات لا يتضمن الملفات، وفق [وثائق Supabase](https://supabase.com/docs/guides/platform/backups).
4. يجب التقاط أعداد ومعرفات المصدر من **نفس snapshot المستخدمة للتصدير**، وحفظ المعرفات داخل الوسيط الآمن فقط، ثم مقارنة القيم/المجموعات فعليًا داخل البيئة المعزولة. التقرير العام يتضمن الأعداد ونتيجة التطابق فقط. تُقاس مدة النسخ والتشفير والاستعادة والتحقق كل على حدة، وتُختبر قابلية فك التشفير.
5. معالجة فرق default privileges في مرجع البروفة أو توثيق استبعاده واعتماده؛ لا تعديل للإنتاج ضمن هذه المهمة. المقارنة لا تغطي عضويات/إعدادات الأدوار العامة ولا جميع مخططات النظام وStorage/Vault أو إعدادات Auth الخارجية وPostgREST. لا تدّعي استعادة مشروع Supabase بكامل خدماته. جُردت الإضافات الحية فقط، ولم تُثبت مطابقتها جميعًا في المرجع.
6. تبقى قرارات المنتج والتشغيل السابقة، ومنها الخدمات التي تحتاج مختصة وسياسة القناة ومالك الاستعادة ونافذة التنفيذ، مفتوحة كما في دليل الإصدار. لم تُغير بيانات العمل.
